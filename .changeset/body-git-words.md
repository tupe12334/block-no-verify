---
'block-no-verify': patch
---

Stop blocking a long one-line commit message or PR body because it has many `git` words. When a command is too large to check, it is now checked once more with each quoted `-m`, `--message`, `--title`, `--body` or `--notes` value (not the `--body=…` form) of a `git` or `gh` statement replaced by a short placeholder, because the shell never runs that text. The full check runs on that masked copy, so all text outside the values is checked as in a small command. The masked copy must also have no `--no-verify`-style flag (including prefixes and quote-split forms) and no hook-manager env var for any guarded git command, and the command must have no other hook-skip signal; otherwise it stays blocked with the "could not check this command" reason. Only a value whose whole shell word is exactly one quoted part (`"…"` or `'…'`, with nothing attached before or after it, and no `$` or backtick inside) is replaced, in a command with no `#`, `alias`, heredoc, `$'…'` or `$"…"` quoting, or unquoted newline. Commands that are not too large to check get the same result as before. Since 1.4.5, `detectGitCommand`, `hasNoVerifyFlag` and `hasHooksPathOverride` throw an `InputTooLongError` when their input is too large to check; their docs now say so. `checkCommand` blocks such input and does not throw.
