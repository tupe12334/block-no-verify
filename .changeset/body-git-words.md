'block-no-verify': patch
---

Stop blocking a long one-line commit message or PR body because it has many `git` words. When a command is too large to check, it is now checked once more with each quoted message value (not the `--body=…` form) replaced by a short placeholder: only `-m`/`--message` of `git commit`, `git tag` and `git stash push`/`save`, `-m` of `git merge` and `git notes add`/`append`, `--title`/`--body` (`-t`/`-b`) of `gh pr` and `gh issue` `create`/`edit` (`--body`/`-b` for `comment`/`review`), and `--title`/`--notes` of `gh release create`/`edit`. The program word must be literally `git` or `gh`, with the sub-command right after it replaced by a short placeholder, because the shell never runs that text. The full check runs on that masked copy, so all text outside the values is checked as in a small command. The masked copy must also have no word that is a `-n`-style short option or a `--no-verify` form, whatever option comes before it, no `--no-verify`-style flag (including prefixes and quote-split forms) and no hook-manager env var for any guarded git command, and the command must have no other hook-skip signal; otherwise it stays blocked with the "could not check this command" reason. Only a value whose whole shell word is exactly one quoted part (`"…"` or `'…'`, with nothing attached before or after it, and no `$` or backtick inside) is replaced, and nothing is replaced when the command has a backtick, `$(`, `<(`, `>(` or `eval`, in a command with no `#`, `alias`, heredoc, `$'…'` or `$"…"` quoting, or unquoted newline. Commands that are not too large to check get the same result as before. Since 1.4.5, `detectGitCommand`, `hasNoVerifyFlag` and `hasHooksPathOverride` throw an `InputTooLongError` when their input is too large to check; their docs now say so. `checkCommand` blocks such input and does not throw.
